# npm CLI release guide

The approved distribution pattern follows [AllenMuu/mysql-cli](https://github.com/AllenMuu/mysql-cli#install): an npm wrapper acquires a precompiled Go binary from an exact-version GitHub Release. Agent Manager forwards `install` to the existing Skill command and uses `npm install -g` for persistent CLI installation.

## Local validation

```sh
npm test --prefix dist/npm
go test ./...
go vet ./...
goreleaser check
goreleaser release --snapshot --clean
node dist/npm/scripts/smoke.cjs
(cd dist/npm && npm pack --dry-run --ignore-scripts)
openspec validate distribute-cli-via-npm --strict
```

The smoke test packs only the wrapper sources, installs the tarball into isolated global and project npm prefixes with lifecycle scripts disabled, then acquires the real snapshot binary through the checksum/extraction path and runs the CLI through the global shim and npx. No live npm publication is involved. GoReleaser outputs six archives and checksums.txt to `.goreleaser-dist`; it never cleans committed `dist/npm` sources. Snapshot archives verify builds but are not published stable releases.

## First publication

1. Merge the validated distribution code and `.github/workflows/release.yml` into the release branch. Choose a stable nonzero version such as `0.1.0`; check existing npm versions and GitHub tags first. Source package version `0.0.0` deliberately cannot acquire a binary or be published.
2. Create and push the matching `vMAJOR.MINOR.PATCH` tag. The workflow runs Go/Node checks, builds all platform binaries and publishes a GitHub Release with checksums.txt. npm publishing is disabled until repository variable `NPM_PUBLISH` equals `true`.
3. For the first npm publication, either configure repository secret `NPM_TOKEN` for a publisher authorized for `@allenmuu`, or authenticate locally with `npm login`. Never store the token in the repository.
4. Set `NPM_PUBLISH=true` and dispatch the `release` workflow with the existing tag to publish through CI. For manual local publishing, check out that stable tag, set `dist/npm/package.json` to its matching version using `npm version <version> --no-git-tag-version --ignore-scripts`, verify all six GitHub Release assets against checksums.txt, and run `npm publish --access public` from `dist/npm`.
5. Verify the actual registry package and installation in a clean environment:

```sh
npm view @allenmuu/agent-manager version
npx @allenmuu/agent-manager@0.1.0 --help
npm install -g @allenmuu/agent-manager@0.1.0
agent-manager --help
```

Replace `0.1.0` with the released version. A dry run or local fixture installation is not proof of registry publication. npm versions are immutable; do not reuse an already published version.

## Subsequent releases and retries

After the initial package exists, configure [npm trusted publishing](https://docs.npmjs.com/trusted-publishers/) for owner `AllenMuu`, repository `agent-manager`, workflow `release.yml` (without a path). The workflow grants `id-token: write`; Node 24 and npm >=11.5.1 support OIDC. Remove the bootstrap token after trusted publishing is configured, or retain a suitably scoped valid token if preferred. Public provenance is generated by CI.

Keep `NPM_PUBLISH=true`. Push a new stable version tag; the workflow publishes npm only after the GitHub Release succeeds and all six archives match checksums.txt. Prerelease tags are intentionally rejected. If GitHub publication succeeds but npm fails, fix publisher authorization and manually dispatch the workflow with that same release tag; it verifies assets without recreating the release. If the npm version is already published, choose a new version instead.

## Distribution boundary

Only installation/first-run acquisition downloads the application binary. Existing managed-skill workflows continue to use the local library and do not install dependencies, fetch remote Skills or execute Skill code. Downloads require HTTPS, use bounded redirects/size/timeouts, extract only the expected executable and verify SHA-256 against the same release's manifest. This guards against corruption; it is not independent publisher authentication.
