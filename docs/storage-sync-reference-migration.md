# 存储与同步：Skill 入库与现有引用迁移方案

- 日期：2026-10-15
- 状态：方案草案，尚未实现
- 适用页面：Web 控制台「存储与同步」

## 1. 背景与目标

用户现有的 Skill 分布在 `~/.agents/skills`、`~/.claude/skills`、`~/.codex/skills` 等全局目录和项目目录中。其中部分入口是软链接，可能经过多个中间链接才指向真实文件。

直接移动真实目录会使现有链接失效；仅复制入库虽然保留了现有使用方式，但项目仍引用旧来源，没有交由 Agent Manager 管理。

本方案将同步划分为两个可独立确认的阶段：

1. **复制入库**：解析真实来源，将选定内容复制到配置的 Skill library，保留源目录和现有链接。
2. **迁移已有引用**：将明确选中的现有入口切换到库中的对应 Skill version，并登记为 Managed skill 的 Global activation 或 Project activation。

默认库为 `~/.agent-manager/skills`，实际使用当前配置的路径。入库、引用迁移和后续版本更新分别表达，不以入库成功代替迁移完成。

## 2. 当前实现与需要补齐的能力

当前页面已支持：

- 从全局及当前注册项目的受支持目录发现真实 Skill 目录。
- 按 Skill ID 和内容摘要分组、预览并复制入库，保留来源。
- 设置 `auto`、`symlink-only`、`copy-only` 三种激活方式。
- 对已有操作记录的托管激活进行分范围重新同步和撤销。

当前来源扫描会跳过尚未由 Agent Manager 管理的软链接；现有重新同步操作也不会自动接管这些外部入口。

本方案新增软链接真实来源发现、已有引用关系展示，以及经过预览确认的引用接管。保留既有的版本库、全局和项目独立操作日志及确认机制，同时扩展按入口维护确定版本、依赖感知撤销和写前持久恢复记录。后面三项是本次实施的必要工作，不能视为现有日志机制已经提供的能力。

## 3. 范围与非目标

第一版只读扫描和导入来源范围：

- 当前用户的受支持全局 Skill 目录，包括 Agent 专属目录和 `.agent/skills`、`.agents/skills` 等中立来源。
- 当前 Web 控制台注册项目中的受支持 Skill 目录。
- 从这些入口发现的软链接链及其最终真实 Skill 目录，用于验证和复制内容。

引用写入范围与来源范围分别定义：第一版只接管全局及当前注册项目中 Claude、Codex、Pi 适配器明确支持的 Skill 入口，即对应的 `.claude/skills`、`.codex/skills`、`.pi/skills` 下的选中条目。

`.agent/skills`、`.agents/skills` 仅作为只读导入来源，即使其中条目是软链接，也不提供迁移、托管登记、重新同步或迁移撤销。页面将其标为「仅可导入，暂不接管」。不为接管这些中立目录放宽现有日志路径白名单。

解析出的中间目录或最终来源不会因被发现而获得写入授权。中间入口若本身属于上述适配器位置，也必须单独列入预览并被选中才可修改。

本期不包括：

- 递归扫描整台电脑、自动发现或迁移所有项目。
- 自动删除旧来源、清理失效链接或替换独立真实目录。
- 后台自动同步、自动跟随旧来源变化或自动升级所有激活。
- 执行 Skill 内容、安装依赖或为本流程新增网络访问。
- 将全局和项目操作包装成一个跨范围原子事务。

## 4. 来源解析与分组

### 4.1 展示信息

每个来源条目至少包含：

| 字段 | 含义 |
| --- | --- |
| 发现位置 | Agent 或项目实际可见的入口路径 |
| 来源范围 | 全局或当前项目，以及具体 Agent/中立来源标签 |
| 入口类型 | 真实目录、外部软链接、已管理链接或已管理副本 |
| 链接链 | 原始链接文本、每一跳路径及最终解析结果 |
| 真实目录 | 最终包含有效 `SKILL.md` 的目录 |
| 内容摘要 | 完整 Skill 树的校验摘要 |
| 已发现引用 | 本次扫描中指向该来源的入口集合 |
| 状态 | 可入库、已入库、已管理、内容冲突、失效、循环或不支持 |
| 可执行动作 | 可导入、可迁移或仅可导入；迁移资格与导入资格分别判断 |

保留全局和项目分区，但共享同一分组结果；相同内容不因来源范围不同而重复入库。

### 4.2 解析规则

- 支持相对链接和多层链接，检测循环、失效目标和权限错误。
- 对链接层数、扫描数量、内容读取量设置上限；达到限制时显示扫描不完整及原因。
- 只从服务端发现的受支持入口解析来源。浏览器提交来源标识和选项，不提交任意读写路径。
- 允许入口链接解析到扫描根目录以外的真实来源，但仅检查该 Skill 树，不递归发现其兄弟目录；预览明确展示外部路径。
- 仅放开 Skill 入口及其解析链。Skill 内容树内部的软链接和特殊文件第一版继续拒绝，不盲目展开复制。
- 不将符号链接解析能力泛化为允许任意父目录链接。来源根和写入路径祖先仍须按明确边界验证。
- 已有托管入口按版本归属和操作记录识别，避免重新作为外部 Skill 导入。
- 对解析后的真实来源和配置的库执行规范路径重叠检查；库内合法版本按已管理或已入库处理，不把指向库、库的祖先或重叠目录的入口当作普通外部目录再次复制。

### 4.3 去重与冲突

- 同一个真实目录由多个入口引用：保留所有引用关系，只读取和导入一份对应内容。
- 同 Skill ID、相同内容：合并为一个版本候选，记录全部来源。
- 同 Skill ID、不同内容：展示不同版本，禁止静默覆盖或按扫描顺序选取。
- 库中已有相同内容：复用已有版本，但仍允许继续迁移引用。
- 新 Skill 存在多个不同内容版本时，明确选择库的当前版本；已有当前版本不自动切换。
- 入口名称、真实目录名称与 Skill 身份无法一致解释时，展示为身份冲突，要求明确选择；不自动重命名或合并不同 Skill ID。

## 5. 阶段一：复制入库

用户选中 Skill 后点击「预览入库」，预览列出真实来源、内容摘要、目标版本以及新增、复用或阻塞结果。

确认后执行：

1. 重新验证来源链接链、真实目录、内容摘要和库状态与预览一致。
2. 将完整 Skill 内容复制到库中的独立版本，保留原有版本和当前版本选择规则。
3. 新版本保留有证据的版本来源元数据；每次确认导入同时保存独立的来源发现记录，包含发现入口、解析链、最终来源、内容摘要及对应的库版本。未知信息明确标为未知。
4. 保留所有源目录、全局入口及项目入口。
5. 返回可供下一阶段使用的确定版本，不以库的当前版本代替此次内容版本。

插件或缓存目录中的内容按快照导入，并展示来源说明。插件以后更新不代表库中快照已经更新。

入库批次沿用原子发布和事务归属验证：失败仅回滚本次操作可证明拥有的状态，保留并报告无法安全恢复的内容。

### 5.1 来源发现记录与版本元数据

来源发现记录属于本机操作证据，与不可变版本的 provenance 分开存储。即使内容已入库，也必须保存本次已确认的新来源关系，不能因跳过复制而丢弃；这不会重写既有版本的发布者、原始来源或信任状态。

记录由服务端生成，至少包含记录 ID、批次 ID、观察及确认时间、范围、入口与原始链接链、最终目录、内容摘要、Skill ID、确定版本和新增或复用结果。暂存记录在重新校验通过后才能标为已提交。来源关系是当时的观察，不等于持续跟踪或更新授权。

记录可放在现有 `~/.agent-manager/skill-sync` 本机状态目录，具体格式在规格阶段确定。导入结果必须返回确定版本及对应的发现记录标识，后续迁移重新验证现有文件状态，不能仅信任历史记录。

来源发现记录提交失败时，不开始引用迁移；按第 7.2 节报告待恢复状态。已经成功发布的不可变版本保留，恢复时幂等补齐记录，不将成功版本视为可随意删除的临时文件。

## 6. 阶段二：迁移已有引用

### 6.1 选择与预览

入库完成后在当前页面展示「迁移已有引用」，用户可选择全局入口、当前项目入口，或者暂不迁移。已入库的 Skill 可直接进入这一阶段，不要求再次新增版本。

第一版仅接管第 3 节列出的适配器入口中已存在的软链接。独立真实目录和中立目录条目可作为导入来源，但不在此流程中自动替换为链接或副本。

每个迁移项展示：

```text
入口：项目/.claude/skills/foo
原始链接：~/.claude/skills/foo
最终来源：~/.agents/skills/foo
目标版本：foo / <与原内容对应的版本>
迁移后目标：~/.agent-manager/skills/foo/versions/<版本>
最终形式：软链接或托管副本
```

示例中的 `~` 仅便于阅读，实际保留原始链接文本，文件系统解析与写入使用明确的规范路径。

### 6.2 迁移规则

- 只修改已预览并选中的既有入口，不额外激活其他 Skill、Agent 或项目。
- 迁移到与该入口迁移前内容一致的版本，不顺便升级到另一个当前版本。
- 多层链接迁移后直接引用确定的库版本，减少中间依赖。
- 遵守已保存的同步设置：`symlink-only` 使用链接，`copy-only` 使用有日志归属的副本，`auto` 仅在既有允许条件下回退为副本。
- 链接和副本都记录确定版本、实际写入形式及迁移前后状态，使后续重新同步和撤销可以识别归属。
- 同名但内容不同的本地版本不被其他来源替换；已经发生修改、失效或无法验证内容的入口阻塞迁移。
- 同一入口即使由多条来源关系发现，也只生成一个写入动作。

### 6.3 接管后的按入口维护

按「范围、目标 Agent、入口路径」标识一个激活，并为该入口绑定确定的 Skill ID、版本和实际写入形式。同一 ID 在不同 Agent 入口中可以绑定不同版本。

现有 `internal/lifecycle/resync.go` 按 Skill ID 合并激活，并拒绝同一范围的同 ID 指向不同版本。本次必须调整重新同步的计划和执行模型，使版本选择与内容摘要按入口绑定；不能仅保留现有按 ID 分组的实现。

例如，Claude 的 `foo` 迁移到版本 A，Codex 的 `foo` 迁移到版本 B 后，切换同步模式应分别从 A、B 重建各自入口。不能把其中一个版本分配给两个入口，也不能因版本不同而阻塞整个范围。撤销重新同步时按入口恢复本次重新同步前的形式与版本，不等同于撤销更早的引用迁移。

### 6.4 间接影响与覆盖范围

可能存在未注册项目通过全局入口间接引用 Skill：

```text
其他项目链接 → 全局链接 → 旧真实目录
```

切换全局入口会影响这条链，即使其他项目未进入本次扫描。预览须说明「依赖此全局入口的其他项目也会经过新目标」，并验证首次切换前后内容一致；不能将这些项目标为已经登记接管。

其他项目若直接引用旧真实目录，则继续使用旧内容。保留旧目录可以避免迁移导致其失效，但不能保证这些项目后续会跟随新库更新。

结果页始终显示本次已检查范围，并说明未扫描其他项目。后续全局版本更新仍可能影响经全局入口间接引用的项目，不能承诺这些未扫描项目已固定版本。

## 7. 执行、失败恢复与撤销

### 7.1 确认与并发校验

入库和引用迁移分别预览、分别确认。迁移阶段的全局和当前项目操作按范围分别确认，使用各自日志与锁。

一个范围执行、恢复或撤销后，作废页面上尚未执行的其他范围预览，刷新引用关系并重新确认下一范围。即使最终内容相同，也不能继续使用完整链接链已变化的旧预览。

预览绑定当前会话、注册项目身份、来源标识、完整链接链、内容摘要、确定目标版本、目的入口状态和同步设置。执行获取相应锁后重新检查并验证有效期；任一关键状态变化就拒绝旧预览，要求重新生成。

写入采用暂存、校验和受保护发布，并在日志中记录每个入口的前后状态。恢复时只处理仍属于本次事务的状态，不覆盖并发修改。

同一范围批次内，先验证全部入口和来源依赖，再执行逐入口发布。依赖关系须区分本批次入口与外部节点：本批次已发布的变化按操作记录中的预期状态验证，外部节点仍须匹配确认时的证据，不能把本批次的合法变化当作外部竞态，也不能无差别忽略链接链变化。

### 7.2 分范围结果

- 入库失败：不开始引用迁移。
- 入库成功、迁移未执行：保留新库版本，所有旧入口继续使用原目标。
- 某个范围迁移失败：在该范围内尝试安全回滚，报告成功、已回滚和需要恢复的项。
- 全局成功、项目失败等情况：明确显示部分完成，保留各范围的真实结果，重新预览后才能重试。
- 中断后根据持久操作记录恢复或报告待恢复状态，不将未完成操作显示为成功。

上述中断恢复需要新增写前持久记录。当前生命周期在文件变更后才提交成功操作日志，普通错误路径中的进程内回滚不能覆盖进程被终止的窗口。

入库与每个范围迁移分别使用持久批次 ID，记录计划、来源发现记录、范围及依赖、备份位置、预期 before/after 状态、确定版本和发布进度。协议要求：

1. 在首次修改目标之前，持久保存并同步备份、恢复所需暂存内容及 `prepared` 记录；备份不可用时不开始写入。
2. 每次发布前持久保存该步意图和可验证的事务归属证据，发布后记录进度。操作系统或文件系统不支持所需持久保证时，阻塞执行并说明原因。
3. 全部写入和校验完成后，持久提交成功日志及来源发现记录，再将批次标为 `committed`。状态更新与写入之间的中断必须能通过实际文件状态判定，不只依靠最后一个进度字段。
4. 启动控制台或进入此页面时只读检测未完成批次，展示「待恢复」并阻塞与该批次资源重叠的新写入。用户查看恢复预览后，才能确认完成提交或安全回滚。
5. 恢复重新获取相应锁，按已持久证据验证归属、内容和依赖。无法验证时保留现状及备份并报告冲突；不自动覆盖用户修改。
6. 恢复动作须可重复执行。未完成批次及必要快照不提前清理；已提交迁移所需备份依照现有撤销保留规则保存。恢复成功后刷新页面和相关预览。

这不增加跨范围事务。已提交的入库版本在后续迁移失败时继续保留；全局与项目各自提交、恢复和撤销。

### 7.3 撤销

- 全局和当前项目分别提供迁移撤销预览和确认，遵循对应日志的最新可撤销操作规则。
- 恢复原始链接文本，包括相对路径写法，撤销前验证迁移后的入口仍属于该操作。
- 以「本批次拟恢复的 before-state 覆盖当前文件系统」构造只读视图，验证恢复后的完整引用链。批次内入口使用各自备份与事务归属证据，批次外节点使用持久依赖记录重新校验；不能仅在恢复前沿当前链接链作一次比较。
- 例如同批迁移 `Claude/foo → Codex/foo → S` 后，撤销须验证拟恢复的 `Claude/foo → Codex/foo → S`，允许 Codex 入口由同一批次恢复；不把本次迁移产生的 Codex 变化误判为外部修改。
- 原始链接链及其来源内容摘要、批次内外依赖分类须持久记录并绑定到迁移日志。当前日志中的入口快照和迁移后版本信息不足以独立证明原链仍安全，需新增记录和 Undo 校验。
- 批次外链或来源不能匹配证据、恢复后失效或内容变化时，报告冲突，不静默恢复。允许差异必须来自已验证的本批次恢复计划，不能仅因内容相同就忽略外部链变化。
- 用户在迁移后手动修改的入口不被撤销覆盖。
- 撤销引用迁移保留已导入版本，避免破坏其他项目的激活。
- 成功入库不提供自动删库式撤销；本流程无法证明其他项目没有引用该版本。

对于 `项目 P → 全局 G → 来源 S`，若先迁移 G，再刷新并迁移 P，默认按相反顺序撤销：先撤销 P，再刷新并撤销 G。P 的 before-state 是迁移 G 之后的实际状态。若先撤销 G，则 P 原依赖已变化，P 的旧撤销计划失效；重新预览后仍无法匹配依赖证据时阻塞，不自动串联撤销其他范围，也不覆盖其入口。页面展示依赖原因与建议顺序，不承诺任意顺序都能撤销。

## 8. 页面流程

```text
扫描来源
  → 选择 Skill
  → 预览并确认复制入库
  → 选择已有引用
  → 按范围预览并确认迁移
  → 查看结果 / 撤销迁移
```

页面保留现有区域，并做以下调整：

| 区域 | 变更 |
| --- | --- |
| 库与同步设置 | 保留库路径及三种同步模式，解释设置对迁移和后续激活的作用 |
| 来源清单 | 增加真实目录、链接链、入口类型、引用数量、迁移资格和诊断信息；中立目录标为仅可导入 |
| 入库预览 | 显示新增或复用版本，明确源文件与现有引用保持原样 |
| 迁移已有引用 | 新增入口选择、版本对应关系、间接影响说明及分范围确认 |
| 操作结果 | 分别展示入库与迁移结果、已覆盖范围、待处理项、依赖顺序和撤销入口 |
| 待恢复批次 | 展示未完成状态、受影响资源与恢复预览，确认后恢复，冲突时保留备份 |
| 重新同步已管理 Skill | 按入口维护确定版本，支持同 ID 的不同入口版本并保留各自内容 |
| 上游更新 | 保留独立操作，不由入库或迁移隐式触发 |

中英文文案同时更新。无注册项目时仍可处理全局范围；项目区域说明需要注册项目，不提供跨项目任意路径写入。

失效、循环、权限不足或不支持的来源可查看原因，不能进入确认执行。取消预览不产生文件修改。

## 9. 实现拆分

1. **规格与文档**：实施前更新来源同步、项目安装相关 OpenSpec 合同及受影响 ADR，明确来源和可写入口白名单、逐入口版本维护、恢复及撤销依赖；本方案本身不代表规格已更新。
2. **来源与引用模型**：扩展 `internal/skillsync/sources.go`，实现受限入口解析、引用关系和批次依赖图；分别判断导入资格与迁移资格，保留内部树安全与真实路径重叠检查。
3. **入库与来源证据**：扩展 `internal/skillsync/service.go`，验证完整解析链并导入确定版本；新增独立来源发现记录，覆盖复用已有版本的情况，不改写不可变版本 provenance。
4. **逐入口维护模型**：调整 `internal/lifecycle/resync.go` 及计划、版本绑定和执行接口，使相同 ID 的不同入口可维护不同版本。此能力及其撤销验证完成后才开放引用接管。
5. **持久恢复与依赖撤销**：扩展 `internal/operation` 相关本机记录、迁移日志与 Undo 校验，增加写前状态、幂等恢复和基于拟恢复视图的依赖验证；保留全局和项目各自的锁与日志边界。
6. **引用迁移服务**：新增明确的外部引用接管操作，复用并扩展已有安全发布机制；只允许适配器支持的入口，不放宽原有重新同步归属检查或中立目录的日志写入白名单。
7. **本地 API**：在 `internal/webconsole` 增加迁移、撤销和恢复的预览与执行能力；浏览器只传服务端标识、选中项和确认计划，执行后失效其他范围的待执行预览。
8. **页面与本地化**：调整 `web/src/App.tsx` 的 `StorageSyncPage` 及相关类型、组件、文案和测试，覆盖仅导入、已入库直接迁移、依赖冲突及待恢复批次。

具体 API 路径、数据类型和限制数值在规格及实现任务中确定，但必须保留上述行为边界。

## 10. 验收标准

| 场景 | 预期结果 |
| --- | --- |
| 真实目录复制入库 | 源内容和所有现有链接不变 |
| 相对、多层软链接 | 正确展示每一跳及最终来源，入库内容完整 |
| 多入口引用相同 Skill | 入库一次，保留全部已发现引用关系 |
| 同名不同内容 | 保留不同版本，不静默覆盖或升级 |
| 同范围 Claude/foo 为 A、Codex/foo 为 B | 迁移后可逐入口切换链接和副本，并撤销重新同步，各入口始终保留 A/B 对应内容 |
| 内容已经入库 | 复用版本，仍可迁移已有引用 |
| 已有版本发现新增来源 | 幂等保存独立发现记录，既有版本 provenance 与信任状态不变 |
| 只确认入库 | 项目和全局继续使用原入口与原内容 |
| 确认迁移 | 只切换选定入口，迁移前后内容一致，日志识别为托管激活 |
| 全局入口存在间接依赖 | 预览说明影响，不宣称未扫描项目已接管 |
| 未扫描项目直接引用旧目录 | 因源目录保留而继续有效 |
| 独立真实目录入口 | 可导入，不在引用迁移中自动替换 |
| 全局及项目中立目录的真实目录或外部链接 | 仅可导入，不产生接管、托管维护或 Undo 动作；原入口不变 |
| 真实来源与库重叠 | 不递归复制库到库；合法版本识别为已管理或已入库，其余阻塞并诊断 |
| 内部软链接、特殊文件 | 阻塞导入，展示明确诊断 |
| 失效、循环、权限错误或超限 | 无写入，展示失败原因或扫描不完整状态 |
| 预览后链接、父路径、源内容、版本或设置变化 | 拒绝旧预览，不越界读取或覆盖 |
| 各种同步模式 | 最终形式与预览一致，副本具备可验证归属 |
| 失败、并发修改或进程中断 | 仅安全回滚事务拥有的状态，结果和恢复信息准确 |
| 撤销迁移 | 恢复可验证的原始链接，保留库版本，不覆盖后续修改 |
| 同范围 Claude/foo → Codex/foo → S 同批迁移和撤销 | 使用事务预期状态及拟恢复视图验证依赖，合法批次可完成，不误判自身变化为竞态 |
| 项目 P → 全局 G → S 分范围操作 | G 完成后刷新 P 预览；按相反顺序可安全撤销，顺序不兼容或依赖变化时明确阻塞 |
| 发现记录提交失败或发布前后强制终止进程 | 可检测未完成批次，保留成功版本及备份；确认恢复后幂等完成，不虚报成功 |
| 迁移发布中、成功日志提交前后强制终止进程 | 根据写前证据和实际状态识别归属，确认恢复或回滚；再次中断后仍可恢复 |
| 存在待恢复批次时发生新写入或用户改动 | 重叠写入被阻塞，恢复不覆盖无法证明归属的状态 |
| 中英文与无项目场景 | 文案、范围限制和按钮状态一致 |

实施验证应包含来源解析和迁移的回归测试、文件系统失败与并发场景、Web API 和页面交互测试，再运行完整 Go 测试、构建以及仓库约定的前端和 OpenSpec 检查。本文仅记录验收要求，不声明这些测试已经运行。
